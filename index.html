Storage format in this build

No saved copy loaded. New synthetic copies use canonical v5.

New copies use canonical v5 with the explicit compact-json-v1 value codec, source and derived codec 2, locator catalog 3 and physical root protocol 4. Existing per-record v1, fragmented v3 and canonical v4 copies keep their formats. A schema version names a file format, not the app release.

Changed v5 saves batch tree edits and retain only final reachable new pages. Full financial validation remains. Opening a copy still verifies and loads the complete canonical ledger and retained history. This is not bounded-memory application loading. Existing folders are not silently converted. Use the backup guide for an explicit fresh v5 copy that preserves legacy history.
